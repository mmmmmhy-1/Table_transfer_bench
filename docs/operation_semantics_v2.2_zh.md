# Table Transformation Benchmark V2.2 — 七类语义操作定义与边界判定

> **规范澄清：2026-11-19。** 本文与 [V2.2 总标准](benchmark_standard_v2.2_zh.md)、[标注 SOP](annotation_guidelines_v2.2_zh.md) 配套。本次仅修订文本定义和未来标注规则，**不增减 OP1–OP7 / 子型 ID，不更新旧 Case ID、Metadata、Input、Gold、Evaluator 或 Schema**。若旧案例的 DAG/分类可能存在争议，留待另一次有证据的审核；不把建议直接描述成已经验证的历史事实。

## 1. 定义对象：Semantic Transformation Primitives

本 Benchmark 的“原子操作”是**用户目标中独立、可验证的语义转换单元**，不是 `pivot`、`merge`、`concat`、`merge_cells` 等某个库 API，也不是数学上唯一的最小关系代数算子。对 Agent 的评测针对**最终语义结果**，不要求复制 Gold 构建脚本的执行轨迹。

- **语义事实（fact）**：由实体/维度键、指标、时间、值、单位、缺失状态及必要上下文确定的信息；不同的行列位置可以表达同一个事实。允许的事实保留必须考虑重复次数，不能简单用 set 去重。
- **记录粒度（record grain）**：哪些业务维度共同确定一条逻辑记录，例如 `(Company, Employee ID)` 或 `(Region, Year)`。物理行数不是记录身份的充分证据。
- **独立语义输出目标**：可以单独写入 Prompt、独立制定后置条件、通过 Canonicalization / Evaluator 检查的业务变化。若某变化只是另一目标必不可少的机械副作用，不单独计一个 OP。
- **结构语义（structural semantics）**：单元格所属的行/列父子路径、分组身份及其表达；不是字体、颜色、标题装饰、单纯有合并单元格的输入事实。
- **逻辑表（logical table）**：拥有独立字段语义与记录集合的数据块；多个逻辑表可以同属一个 XLSX Sheet。

## 2. OP1–OP7 规范定义（ID 与历史英文名称均保留）

| OP | 历史名称（保持兼容） | 主要语义输出目标 | 正确性不变量 / 核验重点 |
|---|---|---|---|
| OP1 | Reshape | 重新组织**已有**事实的行列维度、记录粒度或宽长表形态 | 维度路径与值的对应关系、单位、缺失状态、事实多重集合不丢不增；新物理行不等于新事实 |
| OP2 | Derive Column | 对已有记录身份生成**新语义属性**（Derived Attribute Generation） | 既有记录粒度、原值保持；新属性的业务规则和计算精度正确 |
| OP3 | Generate Rows | 按确定性规则生成**新逻辑记录**（Derived Record Generation） | 新记录的身份、分组、生成条件、计算与完整性正确；不允许无依据预测/补值 |
| OP4 | Field Decomposition | 从一个复合字段拆出两个或多个独立语义组成 | 拆分后字段可追溯原始组成，不能错误配对、遗漏、凭空添加 |
| OP5 | Field Normalization | 将**同一个既有属性**的值统一为指定类型、编码、单位或类别表达 | 业务身份与事实保持；来源/目标表示、歧义及舍入规则明确 |
| OP6 | Table Integration & Decomposition | 改变多个逻辑表之间的关系、合并、记录分配或字段组分解 | 键、基数、Schema 对齐、分区路由与记录覆盖、字段可重建性 |
| OP7 | Structural Transformation | 显式化、扁平化、改变或重建**语义分组与层级路径**（Semantic Structure Transformation） | 每条事实的父子路径/分组正确；有要求时验证有效合并范围；单纯样式不计 |

保留 OP2“Derive Column”、OP3“Generate Rows”、OP7“Structural Transformation”等历史名称，是为了保证 ID 和文档兼容；上表括号中的语义表述用于消除“物理列/行数/合并 API 即标签”的歧义。

## 3. 五组关键边界：正反例与判定规则

### A. OP1 与 OP3：事实重新表示 vs 新逻辑记录

- **OP1 正例**：`Region, 2024, 2025` 宽表转换为 `Region, Year, Value` 长表；物理行数增加，但所有原始 `(Region, Year, Value)` 事实不变。
- **OP3 正例**：除既有记录外，按地区新增 `Mean`、`Sample SD` 或对照差值记录；新增记录的业务身份、计算规则独立。
- **反例**：仅因为 Unpivot 后输出行数翻倍，就给 OP1 任务附加 OP3。
- **G4 边界**：补齐未出现的月份/维度组合（保持值为空或使用指令规定的确定规则）可算 OP3；没有来源/规则的数值推测不属于核心任务。

### B. OP2 与 OP3：在既有 grain 上加属性 vs 创造新的 grain

- **OP2 正例**：每位员工记录增加 `Performance Score`；每个国家现有行增加 2015 对 2014 同比列。
- **OP3 正例**：每个部门新增一条 `Average Salary` 统计记录、为实验组插入一条 `+TNF minus -TNF` 差值行。
- **反例**：生成汇总行用了 AVG 计算，就额外标 OP2；没有独立新增的属性目标时仅标 OP3。
- **边界提醒**：同一个统计函数可以出现在 OP2 或 OP3；取决于派生结果附着的**逻辑记录身份**，不是公式名称。

### C. OP4、OP5 与 OP2-D3：拆组成、规范化、派生新属性

- **OP4 正例**：`CHN|18/03/2025|1250万元` 拆为 Country、Date、Amount。
- **OP5 正例**：已识别的 `CHN` 规范为 `China`、`18/03/2025` 规范为 ISO 日期、`1250万元` 在明确单位规则下转换为人民币元。
- **OP2-D3 正例**：从已有 Country 派生 Region；根据 Amount 产生独立 Risk Tier。
- **反例**：仅把 Country 编码转换成名称，就因为新增一个输出列而标 OP2；或者把新属性 Region 当作原 Country 的“同一值规范化”。
- **可组合示例**：从复合字段拆 Country/Date/Amount（OP4）→ 对拆出的 Date/Amount 统一单位/格式（OP5）。只有前一步产物是后一步必需的语义输入时才连 DAG 边。
- **强制消歧**：含糊日期 `03/04/2025`、货币汇率、编码词典、缺失/错误值与舍入规则必须在 Prompt 或输入依据中充分确定；否则拒收。

### D. OP6 与 OP1：跨逻辑表关系 vs 单表维度形态

- **OP6 正例**：按地理身份对齐独立行业统计数据块；追加相同 Schema 的独立分表；按 Sex 分配记录到不同工作表（授权排除源汇总行时须明确说明）。
- **OP1 正例**：单一事实表 Year 列 Unpivot 为 Year/Value 记录。
- **共同出现**：六个行业数据块整合并输出行业长表，需要完成跨表整合（OP6）和维度重塑（OP1），但可用“先 Join 再 Unpivot”或“先逐块 Unpivot 再 Append”等等价执行路线。
- **反例**：只因为某脚本用了 `concat` 就标 OP6；只因 `merge` 了 pandas 表就推断是 OP6 的某种 Join；一条业务目标不能从实际代码中倒推多个标签。
- **J 子类粒度**：J1–J4 为 Join（匹配键/基数），J5 为 Append（字段对齐/重复保留），J6 为 Partition（路由/覆盖），J7 为 Split Columns（共享身份/可重建）。**统计时必须分别报告四组覆盖与成功率**，OP6 总平均只能作为补充。
- **路径非唯一**：J 子型表达标注的关系契约和目标，而非对 Agent 参考脚本的执行步骤约束。不同合法实现不影响输出 Hard Task Success。

### E. OP7：语义层级变化 vs 纯样式/输入结构

- **T1 Group Representation Conversion**：已知父组与成员关系，将其合并表达或显式展开，例如公司/员工分组的合并单元格与平铺组名相互转换。
- **T2 Hierarchical Flattening**：`Gene → Experiment → Replicate → Ct` 展开为保留完整路径的单层字段标识。
- **T3 Hierarchy Construction**：根据已存在的 Year、Metric 等维度字段重建新的多级表头，或建立必要的多层分组编码。
- **正例**：将复杂多层列标题转为语义无歧义的单行标题；根据显式分组维度重建可校验的行/列父子层级。
- **反例**：合并标题 `A1:H1`、统一颜色、改变边框、保持源表已存在的合并状态，或仅仅在 Input 中遇到 S1/S2/S3。
- **核验**：父子路径正确、分组成员无误、需要时验证有效合并范围；不把装饰性合并坐标当作主要正确性条件。
- **T1/T3 判定**：已知分组在不同物理表示之间转换优先 T1；由显式维度设计新父子层级优先 T3。一个结构输出目标不因为同时调用 merge/unmerge 而重复计同一个 OP7。
- **与输入结构分离**：S0–S4 只能描述 Input；Gold 可以单独记录 Output 的层级属性，但不改变 OP7 的语义门槛。

## 4. 标注流程：一个可重复的判定决策树

1. 从 Input 与用户指令抽出**完整业务事实、输入结构、输出要求**，先确认最终答案可确定。
2. 问：输出只是把已有事实重排为新维度/粒度？→ OP1；是否额外新增新的逻辑记录？→ OP3。
3. 问：新增的是在既有记录身份上的新属性？→ OP2；不要因为使用公式或物理列数变化重复标注。
4. 问：是否从复合单元格解出多个属性？→ OP4；是否需要规范化同一个属性的值？→ OP5；是否推导新业务属性？→ OP2。
5. 问：是否跨独立逻辑表执行键匹配、追加、按行分区、按列分组拆表？→ OP6；每个 OP6 节点补充现有 Schema 要求的 `subtype` 与 `table_contract`。
6. 问：输出是否独立要求变换**语义父子路径/分组表达**？→ OP7；如仅颜色、标题合并或保持已有结构，则不是 OP7。
7. 对每个标签记录四项**审核契约**：Precondition（所需事实/业务约束）、Semantic Effect（目标变化）、Invariant（必须保持的语义事实）、Postcondition（可验证的成功条件）。
8. 对节点间依赖连边前问：“如果不先满足 A 的语义目标，B 的目标还能否根据原始来源独立正确完成？”能则通常不连 `A→B`；只存在实现步骤顺序不能建立依赖。
9. 确保 Prompt、Gold、Evaluator 三者对同一个目标的允许表示一致；对未要求的行列坐标/装饰性合并不得暗扣。

## 5. 必须统一的评测口径

| 操作 | 核心不变量 | 至少一个典型错误注入 |
|---|---|---|
| OP1 | 事实多重集合、维度→值映射与单位 | 错误地交换年份/指标值 |
| OP2 | 既有记录键、源值与派生公式语义 | 将归一比例误当作百分点 |
| OP3 | 新记录身份、分组、数量、生成数值 | 漏新增一组统计行 |
| OP4 | 复合字段组件、关联和覆盖 | 拆字段时把两个组件错配 |
| OP5 | 同一属性的目标类型/单位/编码、缺失 | 把 `N/A` 或缺失改成零 |
| OP6 | 键/基数/路由/覆盖/可重建性 | Join 错键或 Partition 漏行 |
| OP7 | 语义路径、分组成员与必需合并关系 | 跨父组错误合并 |

- 主榜单继续使用 Hard Task Success；另单独报告 OP6 四个子组、S0–S4、单/多操作组合、结构提示消融与必要的规模控制实验。
- 为避免把输出更大或指令更长导致的失败全部解释为“组合能力不足”，组合实验宜控制来源、事实量、结构及预算，辅以单 OP 诊断任务。
- 对语义等价但物理布局不同的输出，应在 Prompt 约束允许范围内接受；对错误数值、错关联、错误层级、未经授权删数据应拒绝。
- `operation_nodes` 与 `dependency_edges` 是**标注层语义模型**，不要作为 Agent 必须采用的执行规划。必要依赖可以由任务中间产物/不变量支持；模型最终正确并不代表其执行过某条参考轨迹。

## 6. 向后兼容与执行边界

- 保留 V2.2 版本号、OP1–OP7、R/D/G/F/N/J/T 子类型 ID、现有 Case ID 和分类目录。
- **本次不修改** `data/`、`schemas/`、`examples/`、各案例 Prompt、Gold、Evaluator 或 Metadata。OP6 `table_contract` 现有机器契约继续有效。
- Precondition / Semantic Effect / Invariant / Postcondition 目前是**人工审计清单**，不作为新机器 Schema 必填属性；以后如需机器强制验证，单独设计 Schema 升级及兼容策略。
- 旧案例的 DAG 若怀疑存在按参考执行顺序误连边（例如某些已有计数可直接由原始记录得到），须另行做证据化审核，不能在此次定义更新中直接修改或声称旧数据错误。
- 这是**操作定义与标注规范的文档修订**，不构成新数据规模、Agent 成功率或 ACL 可行性的实验验证。
