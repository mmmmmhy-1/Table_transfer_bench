# Table Transformation Benchmark V2.2 — 数据构建标准（中文）

> 状态：取代 V2.1 的当前主标准（V2.1 文档留存历史版本）。操作分类扩展至 OP7；旧案例 ID 为稳定标识，不因版本升级自动重命名。
>
> 项目当前采用的 **Agent-Oriented V2.2 工作标准**。适用于新增样本、旧数据迁移、标注审核、自动评测与论文实验。本文规定的是**设计与验收要求**；其中“建议规模/比例”是建设目标，不能理解为已经实现的统计结果。
>
> 配套文件：[标注指南](annotation_guidelines_v2.2_zh.md) · [Metadata JSON Schema](../schemas/case_metadata.schema.json) · [仓库数据组织](../data/README.md)

## 1. 定位与基本任务

**任务**：给定一个或多个 XLSX 工作表及自然语言指令，LLM Agent 可以自主读取表格、调用 Python/Pandas/OpenPyXL 等允许的工具，生成符合指令的完整 XLSX 结果，并由独立评测器核验。

- 输入：`input.xlsx` + `instruction.txt`（必要时多个输入工作簿需在 Metadata 中明确）。
- 输出：`submission.xlsx`，与 `gold_output.xlsx` / `gold_canonical.json` 比较。
- 主目标：量化原子操作能力、复杂结构下的可靠性、组合泛化能力。
- 扩展目标：失败传播、规模鲁棒性、Agent 效率。
- **不**把开放式 TableQA、OCR、没有确定规则的预测、自由视觉排版、网络外部信息搜索列为核心任务。
- 模型实现可采用不同规划与工具调用方法；主榜单固定环境与预算，**不**要求沿用某个预设步骤。

### 研究问题

| 编号 | 问题 |
|---|---|
| RQ1 | 七类原子操作分别能否成功执行？ |
| RQ2 | 多级表头、行层级、合并与不规则布局如何影响成功率？ |
| RQ3 | 已掌握单原子操作能否组合执行，能否泛化到未见组合？ |
| RQ4 | 错误出现于何处，如何传播到最终输出？ |
| RQ5 | 数据规模变化会如何影响可靠性、工具调用与成本？ |

## 2. 七类核心原子操作

| ID | 英文名 | 中文名 | 明确的输出变化 | 子类型建议 |
|---|---|---|---|---|
| **OP1** | Reshape | 表格维度重塑 | 维度在行/列之间重组，正确保持原始事实 | R1 宽转长、R2 长转宽、R3 多维重塑、R4 复杂维度重组（不含纯表头结构变换） |
| **OP2** | Derive Column | 派生列生成 | 基于规则生成一个或多个新列 | D1 算术、D2 条件、D3 映射、D4 跨行计算 |
| **OP3** | Generate Rows | 生成新行 | 新建分组小计、总计、扩展或补全记录 | G1 分组小计、G2 总计、G3 规则扩展/统计、G4 时期/维度补全 |
| **OP4** | Field Decomposition | 复合字段解析 | 从复合单元格提取独立语义字段 | F1 分隔符、F2 模式、F3 语义解析、F4 字段不完整 |
| **OP5** | Field Normalization | 字段值规范化 | 统一值的格式/类型/单位/编码，保留事实 | N1 日期、N2 数值、N3 单位、N4 类别 |
| **OP6** | Table Integration & Decomposition | 表格整合与拆分 | 按键关联、按共同 Schema 合并或按明确规则拆表，核验事实与覆盖 | J1 一对一、J2 一对多/多对一、J3 多对多、J4 多键、J5 纵向合并、J6 按行分区、J7 按列拆表 |
| **OP7** | Structural Transformation | 结构关系转换 | 根据业务语义改变或重建合并范围、行列层级及表头结构，不改变基础事实 | T1 合并/拆分与分组显式化、T2 层级表头扁平化、T3 层级结构重建 |

### 操作边界

1. **按目标输出判定**：例如删除 `Total` 列并要求重建，属于 OP2；删除 `Total` 统计行并要求重建，属于 OP3。即使新行计算涉及聚合，也不再另加 OP2 标签，除非另有真实的“新增派生列”步骤。
2. **结构属性与 OP7 是不同维度**：Mammal/Primate 行层级、多级列表头首先描述输入的 S1/S2/S3 结构；如果任务要求将已有结构关系显式化、拆分或重建，则标注 OP7。若与此同时改变行列数据的维度、记录组织形式，另标 OP1；只要求保留原有结构时不标 OP7。
3. 排序、筛选、定位表头、读取工作簿通常是辅助动作，**不**因 Agent 使用了这些动作就新增操作标签。
4. 复合字段**拆出新字段**属于 OP4；将已有字段统一为 ISO 日期、整数、单位、代码属于 OP5。二者均必要时才组合标注。
5. **OP6 表格整合与拆分**：保留按键关联 J1–J4，并增加 J5 纵向合并、J6 按行分区、J7 按列拆表。关联需明确键、连接类型、基数、空键/未匹配/重复策略；追加需明确字段对齐和缺列；拆表需明确路由、字段去向和完整覆盖。模糊实体对齐不属于核心确定性 OP6。完整契约与挑战构造见 [OP6 增补规范](op6_table_integration_v2.2_zh.md)。
6. **OP1 与 OP7 边界**：OP1 改变记录、维度、宽长表形态；OP7 改变层级关系与合并结构的表示。多级表头随宽长表转换发生改变时，必须核查是否独立存在指定的表头语义变换目标；仅转换产生的必要辅助步骤不自动新增 OP7。纯样式、颜色、行高或无语义作用的合并不计为 OP7。
7. **OP7 子类型**：T1 Merge/Unmerge & Group Explicitization（含分组层级传播、合并区域拆分/重建）；T2 Hierarchical Header Flattening（完整传播父子路径并生成可逆或可核对的列标识）；T3 Hierarchy Reconstruction（由显式路径/字段重建多级表头或行层级）。Gold 必须校验数据事实保留及层级/合并关系，不仅验证是否调用 Excel API。
8. 任何原子操作均应有：明确输入/目标、可独立构造的样本、确定性验证条件、相对清楚的典型失败原因及可组合性。

9. **OP6 与 OP7 边界**：OP6 改变逻辑表之间的组织/关系；OP7 改变单元格合并、层级与表头关系的表示。整表拆分不自动标 OP1/OP4/OP7；只有独立发生维度重塑、复合字段解析或语义结构转换时才组合标注。

## 3. 相互独立的评测维度

### 3.1 输入结构标签（可多选）

| 标签 | 定义 | 主要检查点 |
|---|---|---|
| S0 Flat | 规则单层表头 | 无其他结构异常时使用 |
| S1 Multi-level Column Header | 二级/三级列表头 | 父子列语义与合并范围 |
| S2 Hierarchical Row Header | 多级/分组行表头 | 行类目的父子包含关系 |
| S3 Merged Cells | 有语义作用的合并单元格 | 记录合并区域及所属字段 |
| S4 Irregular Layout | 不规则布局或多个数据块 | 非表头说明行、交错数据块、特殊布局 |

S0 与 S1–S4 通常互斥；S1/S2/S3/S4 可以共存。**S4 不能仅因标题在表外就自动标记**，必须有真正不规则布局的证据。

输入复杂性与输出操作类型相互独立；同一 OP1 可以分别在 S0、S1+S3 下测试。

### 3.2 操作组合

- OP7 可与 OP1/OP2 形成组合：例如 Labor43 中 OP1 展开员工的双列表，OP2 派生统计列，OP7 根据展开后的员工与公司分组重建实际合并范围；DAG 只标业务输出之间可验证的依赖，不能把相邻的机械步骤都算作独立能力。


- 单原子：一个独立的语义转换节点。
- 双原子：两个有数据依赖的节点；不是简单地把无关指令拼接。
- 多步：优先 3 个节点，少量 4 节点扩展。
- 对组合任务保存 `operation_nodes`、`dependency_edges`（有向无环图 DAG）以及有条件时的中间工件/不变量。
- 在未见组合泛化实验中保留部分 **操作依赖模式** 不进入 Train/Dev。仅交换字段名称并不构成新的组合。
- 区分“先后执行”与真正的数据依赖；仅有顺序不一定构成有效组合。

### 3.3 规模（不分 Small/Medium）

**正式取消 Small / Medium 强制划分和固定行列数上限**。规模以连续属性记录：工作表数、数据行总量、最大列数、非空单元格、used range 单元格数、文件大小、合并区域数、输出记录数及扩张倍数（适用时）。

多个表的任务应保留每个 sheet 的独立统计。发布时报告规模分位数及分布；可用同一任务语义构造不同规模的受控实验，不把规模直接作为难度等级。

### 3.4 难度标签（辅助标签，不代替分维统计）

| 等级 | 设计准则 |
|---|---|
| L1 | 单原子 + 平表 + 明确规则 |
| L2 | 单原子 + 复杂结构或复杂规则 |
| L3 | 两个存在真实依赖的原子操作 |
| L4 | 三个及以上真实原子操作，或多操作与复杂结构共同出现 |

L1–L4 是数据组织上的启发式标签，**不是严格的难度全序**，也不是准确率分析的唯一依据；其有效性需通过试点实验检验。

## 4. 数据来源与受控改造

优先次序：已有经清洗且可追溯的真实表格 → 公开真实数据集 → 公开报表 → 基于真实表的受控改造 → 少量人工合成诊断样本。

- 建议核心数据中真实来源或真实表改造占比达到 **80% 及以上**（目标，并非当前已达到）。
- 目标覆盖财务/经营、工业/物流、科研、公共统计、教育/公共服务等至少五个领域；不为满足比例虚构不自然的业务任务。
- 每个样本记录真实的 `source_dataset`、`source_instance`、`source_filename`、`source_url`、`source_family_id`、许可证与改造记录。不得把“可下载”视为“可再分发”。
- 真实表改造后应标记为 `real_benchmark_derived` 或相应来源类型，而不是声称未经修改。
- **允许受控增删改**：如从源表删除已知 Total 列、已知汇总行，由 Agent 恢复；但要消除隐藏工作表、公式缓存、备注等意外答案泄漏，同时保留足以确定结果的源信息。
- 对新增数据的事实/计算必须有参考依据；不得无说明地人工编造缺失业务数值。
- 重复来自同一原表的变体统一 `source_family_id`，不得跨 Train/Dev/Test。

## 5. 统一数据组织

采用用户确定的 **领域 → 编号案例** 结构；来源是属性，**不是文件夹分类**。

```text
data/
  catalog.json
  environment/
    case_1_realhitbench_environment21/
      input.xlsx
      instruction.txt
      metadata.json
      gold_output.xlsx
      gold_canonical.json
      evaluate.py
      README.md
    case_2_<source-short-name>/
  finance/
    case_<N>_<source-short-name>/
  industry/
    case_<N>_<source-short-name>/
```

- 案例文件夹：`case_<N>_<source-slug>`，编号在各领域内唯一且一经公开不重排。
- `metadata.json`：类型、来源、规模、结构、操作 DAG、规则/约束、拆分与发布角色。
- `instruction.txt`：Agent 应看到的自然语言指令。
- `gold_output.xlsx`：标准结果；`gold_canonical.json`：语义对齐与审计使用。
- `evaluate.py` / 共享评测模块：独立检查输出。建议保留生成 Gold 的参考实现，不得把它误当成评测器的唯一“证明”。
- `catalog.json`：全局索引，可按领域、原始来源、OP1–OP7、结构类型、Split 等过滤。

**公开示例可以带 Gold**，但 `split=example`、`release_role=public_demo`，不能用其作为隐藏 Test 成绩。未来正式测试需隔离 Gold 和参考实现。

## 6. 指令编写

> **现行配套规范：**[Agentic 任务指令编写与审核规范](instruction_authoring_v2.2_zh.md)。`instruction.txt` 为 Discovery 主轨道任务；`instruction_guided.txt` 为可选的独立诊断/消融任务。业务约束必须充分，避免用不必要的坐标、原始条目总数或正确派生值提供答案线索。Gold/Evaluator 不得暗扣指令未声明的布局条件。


每条 `instruction.txt` 应包含：所需操作及目标字段、输入依据、保留/删除策略、排序或行插入要求、舍入模式与精度、空值/零值/除零规则、Join 键和未匹配处理（若适用）、提交文件名。

- 不直接复制 Gold Output 数值。
- **Discovery 主轨道**：不直接泄露表头坐标/所有数据范围，让 Agent 自主检查复杂结构；但必须给足决定答案的业务规则。
- **Guided 诊断轨道**：只增加输入结构定位信息；与 Discovery 使用相同业务目标、输出约束和等价判定，分开计分，不额外强制输出合并或实现步骤。
- 原有 `-` 等符号的统计含义要核对来源；若任务约定计算时按零处理，明确说明“不改动原始显示符号”。
- 语义不同但结果可合理多解的指令必须消歧，不能在评测时临时挑选一种解释。

## 7. Gold 与数值正确性

1. 用可复现的参考实现（如 Python、Pandas、OpenPyXL、Decimal）生成 `gold_output.xlsx`。
2. 独立校验 Schema、记录集合（**保留重复次数**）、列/行顺序约束、计算、关系键与完整性。
3. 人工审核关键业务语义与复杂表头；出现争议记录裁决过程。
4. 精确运算优先用 Decimal。原则上在规定结果点才舍入，不能在多个中间步骤无依据地提前舍入。
5. Excel 百分比应区分底层数值（例如 0.15）与显示格式（15%）；类型、单位、日期、空值、文本 `N/A`、数字零及公式缓存应按任务规则区别处理。
6. 如输出顺序未指定可进行语义等价行多重集合比较；如明确指定列序、插入位置和合并范围，则严格核验。
7. 参考结果必须通过检查；另外进行**错误注入**（数值改动、删行、重复行、错列、错分组、破坏合并关系），验证评测器能拒绝已知错误。

## 8. 评测指标与错误分析

**主指标：Hard Task Success**。只有全部必需条件成立（文件有效、Schema 正确、内容正确、约束满足）才记 1，否则为 0；主结果为任务成功率平均值。

辅助指标：Schema Accuracy、Row Count、Row Multiset Match、Cell/Value Accuracy、Numeric Accuracy、Constraint Satisfaction、Preservation Accuracy、Execution Validity、Composition Success。

专项指标：

- OP1：维度映射与事实保持；
- OP2：派生规则与精度；
- OP3：新增行、分组与插入位置；
- OP4：结构字段解析；
- OP5：格式/单位及语义保持；
- OP6：关联键/基数/未匹配、追加字段对齐、重复记录保留、拆表覆盖和分区正确性、字段拆分可重组性。
- OP7：层级路径正确性、有效合并区域、展开/重建后语义等价、原始事实不丢失。

错误类别建议：E1 结构识别、E2 指令理解、E3 Schema、E4 数据映射、E5 计算、E6 数据保留、E7 组合、E8 工具执行、E9 输出约束。允许多标签，区分首个可观察错误与后续传播；不能仅凭模型自述判定根因。

另外记录 Token、工具调用数、执行时间、重试次数、API 成本及超时/崩溃率，效率不与正确性混成单一指标。

## 9. 规模目标、划分与实验

首版 **建设目标**：约 1,200 条高质量任务，其中 720 单原子（60%）、360 双原子（30%）、120 三原子（10%）；先构建覆盖七类操作的试点（各类数量视案例质量与来源而定），通过验证后再迁移原有约 600 条候选数据及补充复杂结构、多表任务。规模目标可按统计充分性与质量审核调整。

建议最终 Train / Dev / Test = 60% / 15% / 25%，在构建阶段确认后冻结；按 `source_family_id` 分组划分，并实施模板与操作组合级近重复检查。对于未见组合测试，额外划分未在训练中出现的依赖模式。**已公开 Gold 的案例不得进入隐藏测试集**。

必要实验：

1. 七种单原子操作；
2. S0–S4 结构复杂性；
3. 单/双/多操作组合；
4. 未见组合泛化；
5. 错误类型与传播；
6. 规模鲁棒性；
7. Guided vs Discovery 结构提示消融。

Agent baseline：ReAct、LLM+Python 单 Agent、Hermes，以及提出方法；模型版本、工具权限、调用次数、Token/时间预算、温度、重试与输出协议需统一记录。LLM-only 对照可报告，但不可与不同工具条件的 Agent 直接混为公平同榜。

## 10. 质量验收与版本管理

**必须通过**：输入/输出可解析；操作标签正确；指令可确定唯一语义结果；Gold 可复现；独立验证通过；来源与许可证可追踪；无训练测试泄漏；Metadata 符合 Schema；复杂案例经独立人工复核；错误注入检查有效。

建议流程：标准冻结 → 每类 20 条试点 → 迁移旧数据 → 扩充复杂结构 → 构建组合 DAG → 去重与人工审核 → 冻结测试集 → 基线实验 → 方法改进。

每次变更任务输入、Gold、指令、校验规则或来源标注应保留 Git 历史与修订理由；影响成绩的修订需更新版本和重新运行评测。正式发布必须报告数据局限性、许可证及已知风险。

---

**V2.2 的研究重点**不是“Excel 函数覆盖最多”，而是**真实复杂表格下，Agent 执行确定性转换与可组合操作的可靠性和失败机制**。
