# Table Transformation Benchmark V2.1 — Agentic 任务指令编写与审核规范

> **适用范围**：所有基于 XLSX + 自然语言指令的 OP1–OP6 数据转换案例。以 Discovery 为**主要评测轨道**，Guided 仅用于独立的诊断/消融。本文补充 V2.1 总标准和标注 SOP，不改变六类原子操作。

## 1. 测量对象与最重要的原则

我们主要衡量 **LLM 在固定轻量级工具调用框架中自主理解任务、发现表格结构、规划与执行、检查并产出有效 XLSX 的能力**。不要让指令等同于“人工给好的执行轨迹”；也不要故意省略决定正确结果的必要业务规则。

| 应明确给出（目标/业务约束） | Discovery 不应默认给出（解题线索/答案） |
|---|---|
| 必须新增/删除/转换的字段及它们的业务含义 | 不必要的 A1、B3、A1:F17 等绝对坐标 |
| 结果列顺序、必须保留的分组关系/格式 | 真实数据的行数、总金额、派生字段示例结果 |
| 计算定义、分母、空值/零值、精度与单位 | Python / Pandas / openpyxl 代码、逐步工作流 |
| 原始信息保留规则、排序要求与唯一文件名 | 现成的 Gold、Evaluator、参考脚本或答案片段 |
| 是否强制实际 Excel 合并单元格或特定样式 | 可以从输入自主判断出的合并区域坐标 |

业务必须明确要求二级表头、合并单元格、分组小计时，可以写明这些**输出约束**；这不同于泄露每个单元格的绝对位置。操作步骤不是输出要求，不要把步骤本身当成评分项。

## 2. Discovery vs Guided

**Discovery 主轨**：每条公开示例的 `instruction.txt`，未来隐藏测试也采用同一原则。指令只能使用 Agent 在真实工作中可得的任务目标、输入说明、留存约束和交付协议。禁止枚举结果总行数、正确统计答案和实现坐标；如果某个位置是业务上不可替代的，须明确理由并记录为任务约束。

**Guided 诊断**：同一个 Input、同一业务目标和同一 Gold，另存 `instruction_guided.txt`；可加入表头/合并范围位置、建议映射或操作顺序，不可引用真实 Gold 的计算结果。两轨**分开统计**，同一主榜单不混用。模型不得同时看到两份指令。

- **必要语义约束 ≠ 泄漏**：如原始 `-` 的算术含义、两个 Skill/Area 列无配对关系、百分比字段的单位必须说清；否则题目不可唯一判定。
- **非必要答案 ≠ 约束**：如 Labor43 原始员工/技能的总计条数、Business13 某个国家的 YoY 计算值，只放隐藏 Gold/Metadata/审计报告。
- **格式要求 ≠ OP5**：设置 `0.00%` 只是派生同比列的显示需求；没有独立字段语义规范化步骤就不增加 OP5 标签。

## 3. 每条指令的推荐结构（而非强制模板）

1. **业务目标**：一句话说明需要得到什么 XLSX，而不是怎样写程序。
2. **输入语义**：简要解释歧义字段和分组关系，不列出所有数据内容。
3. **期望输出**：目标字段、列序、行/列形态、需要保留的层级或合并关系。
4. **必要计算规则**：公式含义、统计口径、单位、舍入、空值/零值/重复项、是否允许文本值。
5. **保留约束**：原始记录、注释、顺序、工作表数量。只有业务需要时才指定特定布局位置。
6. **交付协议**：保存为 `submission.xlsx`，不暴露 Gold 或解释内部评测准则。

给多操作任务规定**可验证的最终状态**；不强制 Agent 先执行 OP1 再执行 OP2，除非两者依赖关系是不可替代的业务事实。操作 DAG 放 Metadata 中供研究者分析。

## 4. 写作—Gold—Evaluator 一致性约束（强制）

1. **Prompt 中明确的条件必须评测**：包括数值类型/单位、百分号精度、原始数据保留、合并关系。
2. **Prompt 没要求的条件不得暗评**：若仅要求把 Notes/Key 放在数据下方，就不能强制匹配 Gold 的 B13、B14 等坐标；可以在不同的语义等价布局中接受正确解。
3. **唯一性审计**：不同合理输出如果语义等价，应编写 canonicalization/equivalence checker；如果输出形式必须唯一，应先把不可替代约束加入 Prompt。
4. **公式与缓存**：接受正确的数值或支持的等价公式。OpenPyXL 常生成无缓存的公式；评测器应在**隔离环境**中安全计算支持的纯数值公式，不应直接运行不可信 Excel 宏、外链或任意 Python 代码。
5. **类型 ≠ 显示**：例如同比 0.2295 配 `0.00%`，与文本 `"22.95%"` 不等价；`Percentage of telecoms world total` 中 0.9 是已有百分点值，不是 0.9 的小数比例。
6. **Gold 只是标准参考表示**：主评测应以明确约束和语义等价关系为准；不要字节匹配或把 Gold 的纯装饰性合并当成强制。
7. **回归测试**：每次修改 Prompt 后必须执行 Gold PASS、至少若干错误注入 FAIL、有效但不同表示的解 PASS；同步更新 Metadata 的 prompt_mode、Evaluator 的可接受行为与文档。

## 5. 当前三个案例的决定

| Case | Discovery 保留的业务要求 | Discovery 不再暴露 | 验收重点 |

| environment21 | Total 列、三条计算行、Mammal/Primate、五类麻醉、原始表头层级 | 精确表头坐标和全部结果规模 | 原值保留、计算、分组、百分比 |
| labor43 | Skill/Area 独立长表化、公司/员工分组合并、两个计数列 | 42/11/48/52 等源数据统计答案、逐格操作方案 | 多值展开、无虚构配对、计数和合并 |

当前案例的 Gold 已公开，因此仅供 Harness 调试和演示，不能作为隐藏测试成绩。正式 split 应以 source_family_id 隔离。

## 6. 提交前人工审核清单

- [ ] 指令不包含 Gold 派生数值、真实条目数量和无必要坐标。
- [ ] 模型不访问 `gold_output.xlsx`、`gold_canonical.json`、`evaluate.py`、`instruction_guided.txt` 或参考实现。
- [ ] 所有强制字段、行/列/组关系及空值/舍入规则均可由指令和输入唯一决定。
- [ ] 结构标签仅来自 **Input**；若 Gold 结构有区别，单独记录 Output 结构。
- [ ] Gold 可重建且与 Input 来源一致，不出现静默数据修改。
- [ ] 对格式/公式缓存的判断符合实际 Excel 语义。
- [ ] 通过 Gold 自检、错误注入、语义等价正例，并通过 Schema/Catalog 检查。
- [ ] 记录 Agent 框架、工具清单、系统提示、上下文预算、最大步数、超时、温度与试验随机种子。

## 7. Prompt / Agent Scaffold 分离

`instruction.txt` 是**用户业务任务**；统一 Harness 的 System Prompt 仅负责工具使用、文件路径、执行权限、停止条件和提交规则。不要在每道任务的业务指令中加入固定的 Python 实现提示，也不要因为模型而定制不同的题目文案。主榜单固定 Agent Scaffold、工具权限、模型预算和重试策略；更换 Scaffold 应报告为独立实验。
